# TEXTREUSE Viewer — ספר מקור מול מועמדי הדאטהסט

המערכת היא יישום מחקר מקומי ללא התקנה וללא בסיס נתונים בצד השרת. בקבצים גדולים היא משתמשת ב־IndexedDB מקומי בדפדפן לאחסון raw לפי דרישה. היא טוענת קובץ JSON אחד או כמה מתוצרי TEXTREUSE, מציגה את ספר המקור בסרגל ימני קבוע, קריאה צמודה מול מועמדי הדאטהסט, סינופסיס של קטע אחד מספר המקור מול כמה מועמדים, המחשות רוחב ומטא־דאטה מספריא.

## מבנה התיקייה

יש להשאיר יחד את הקבצים הבאים:

- `index.html`
- `styles.css`
- `config.js`
- `utils.js`
- `ref-templates.js`
- `data-model.js`
- `sefaria.js`
- `visualizations.js`
- `app.js`
- `start_server.py`
- `start_server.bat`

יש להעתיק לאותה תיקייה קובץ JSON אחד או כמה. קובצי הנתונים אינם כלולים בחבילה.

## הפעלה ב־Windows

1. חלץ את קובץ ה־ZIP לתיקייה חדשה.
2. העתק אליה את קובצי ה־JSON.
3. לחץ פעמיים על `start_server.bat`.
4. השרת יתחיל בדרך כלל ב־`http://localhost:8765`. אם הפורט תפוס, הוא יעבור אוטומטית לפורט פנוי אחר ויפתח את הכתובת הנכונה.

## הפעלה דרך GitHub Pages עם קובצי JSON ב־Google Drive

כאשר האתר רץ ב־GitHub Pages, קריאה ישירה ל־Google Drive נחסמת לרוב על ידי CORS. לכן יש להשתמש ב־Web App קטן של Google Apps Script שמחזיר:

- רשימת קובצי JSON בתיקייה;
- קריאת קובץ JSON לפי מזהה קובץ.

### צעד 1: יצירת Web App

1. פתח Google Apps Script וצור פרויקט חדש.
2. העתק את תוכן הקובץ `google_drive_proxy_apps_script.gs`.
3. ודא שהקבוע `FOLDER_ID` מצביע על תיקיית ה־Drive שלך.
4. פרוס כ־Web App:
	 - Execute as: `Me`
	 - Who has access: `Anyone`
5. העתק את כתובת ה־Web App שיצאה בפריסה.

### צעד 2: חיבור ה־endpoint במערכת

בקובץ `config.js`, עדכן את:

- `remoteSources.endpoint` לערך של כתובת ה־Web App.

לדוגמה:

```js
remoteSources: {
	endpoint: 'https://script.google.com/macros/s/XXXXXXXXXXXX/exec',
	label: 'Google Drive',
	listAction: 'list',
	fileAction: 'file'
}
```

### צעד 3: פרסום מחדש ב־GitHub

בצע commit + push, ולאחר מכן רענן את אתר GitHub Pages. חלון בחירת המקורות יציג גם קבצים שמגיעים מ־Google Drive.

בקבצים גדולים המערכת עוברת אוטומטית למצב streaming דרך Web Worker. מעל 64MB הקובץ אינו נקרא כולו ל־RAM; קבצים מעל 1GB עוברים באותו מסלול, עם מודל קומפקטי ו־raw הנשמר ב־IndexedDB כאשר מכסת האחסון של הדפדפן מאפשרת זאת.

## טעינת כמה מאגרים

- קובץ יחיד בתיקייה נטען אוטומטית.
- כאשר נמצאים כמה קבצים, נפתח חלון בחירה מרובה.
- אפשר להוסיף כמה קבצים גם דרך בורר הקבצים בדפדפן.
- כל מאגר מקבל מרחב מזהים נפרד, ולכן מזהים זהים בקבצים שונים אינם דורסים זה את זה.
- בתפריט `מאגרי מקור` אפשר להפעיל או להסתיר כמה מן המאגרים שכבר נטענו.

## הסרגל הימני: ספר המקור בלבד

- הסרגל הימני אינו מציג ספרי מועמדים, ציוני התאמה או רשומות מן הדאטהסט.
- הכותרת נלקחת מן הכותרת הקנונית של החיבור בספריא, כאשר היא זמינה.
- הרשומות מסודרות לפי כתובתן בתוך ספר המקור, ולא לפי חוזק ההתאמה.
- כאשר כמה קובצי JSON משווים את אותו ספר מקור, אותו קטע מקור מופיע פעם אחת בלבד, והמועמדים מכל הקבצים מצורפים אליו.
- המסננים משנים את רשימת המועמדים, אך אינם משנים את סדר ספר המקור בסרגל הימני.

## תצוגת הסינופסיס

הסינופסיס מוגדר תמיד כ־**קטע אחד מספר המקור מול מועמד אחד או כמה מועמדים שנבחרו עבורו מתוך הדאטהסט**.

1. בחר קטע מספר המקור בסרגל הימני.
2. סמן מועמדים באמצעות תיבות הסימון ברשימת המועמדים, או לחץ `בחר מובילים`.
3. לחץ `פתח סינופסיס`.
4. קטע ספר המקור מוצג בעמודה הימנית הקבועה, ורק מועמדי הדאטהסט מוצגים בעמודות שמשמאלו.

הצבעים מסונכרנים בין שני הצדדים:

- לכל מועמד מוקצה צבע קבוע.
- המילים המיושרות בטקסט המועמד מוצגות בצבע זה.
- אותן מילים מודגשות גם בטקסט המקור באותו צבע.
- כאשר מילה בטקסט המקור מיושרת לכמה מועמדים, היא מוצגת בחלוקה צבעונית.
- כאשר ה־JSON מכיל צבע רק בצד המועמד, המערכת משחזרת את ההדגשה בצד המקור לפי רצף המילים, ובמקרה הצורך גם לפי דמיון צורני זהיר.

### אפשרויות נוספות

- בחירה של X המועמדים המובילים.
- שינוי רוחב העמודות.
- גלילה אנכית מסונכרנת בין כל העמודות.
- הסרת עמודת מועמד בלי לשנות את הדאטה.
- פתיחת כל מועמד מחדש בתצוגת הקריאה.
- ייצוא הסינופסיס לקובץ HTML עצמאי.

## אינטגרציה בין התצוגות

- המסננים הפעילים משפיעים גם על רשימות הבחירה בסינופסיס.
- לחיצה על תא במפת החום, נקודה בתרשים הפיזור או קטע ברשת מחזירה לתצוגת הקריאה המתאימה.
- מתוך קשר נבחר ברשת אפשר לפתוח קטע מקור רלוונטי ולבנות עבורו סינופסיס מן המועמדים הקשורים לקשר.
- מתוך קטלוג הספרים אפשר להוסיף לסינופסיס את המועמדים של הספר עבור קטע הספר הנוכחי.
- הבחירות מסומנות הן בתצוגת הקריאה והן בעמוד הסינופסיס.

## הפניות ומטא־דאטה מספריא

הקובץ `ref-templates.js` מגדיר תהליך היררכי קבוע לפענוח המיקומים:

1. מעבר על כל `source_categories` וזיהוי נקודת המעבר מקטגוריות כלליות לשם החיבור.
2. טיפול ברמות שאחרי החיבור כיחידות פנימיות, כותרות משנה או רכיבי כתובת — ולא כחיבור חדש.
3. אימות כל פיצול אפשרי מול אינדקס ספריא, הקטגוריות שלו ועץ הסכמה שלו.
4. יצירת מראה מקום לפי הסכמה המאומתת; בכתובות תלמודיות מומר גם מספר הקטע הפנימי לדף ועמוד, למשל `176` ל־`89a`.
5. ניסיון תבניות מקומיות חלופיות, ורק לבסוף שימוש בהשלמת השמות של ספריא.

כך נתיב כגון `Midrash › Aggadic_Midrash › Ein_Yaakov › Khullin` מזוהה כחיבור **Ein Yaakov** וכיחידה פנימית **Khullin**; ואילו `Talmud › Bavli › Seder_Kodashim › Chullin › 176` מזוהה כחיבור **Chullin**, כאשר `176` הוא רכיב כתובת ולא שם חיבור.

בתצוגת `אבחון ספריא` אפשר:

- לראות בעיות מבניות מקומיות בקובצי ה־JSON;
- לדגום מראי מקום מכל ספר ולבדוק אותם מול ספריא;
- לראות איזו תבנית נוצרה ובאיזו שיטת פתרון התקבל מראה המקום;
- לקבל הסבר כאשר ההפניה אינה נפתרת, למשל שם ספר לא קנוני, יחידה שאינה תואמת לסכמת הספר או כתובת חסרה.

אם אין חיבור לרשת, הטקסטים, היישורים, הציונים וההמחשות המקומיות ממשיכים לעבוד.

## כללי הנתונים

- `passage_text` הוא קטע הספר הקבוע — הטקסט שמולו משווים.
- `source_text` הוא קטע שנמצא בדאטהסט.
- התאמות עצמיות מוסרות לצמיתות בזמן הטעינה ואינן נכנסות למודל הנתונים.
- בחירה בכמה ספרים או קטגוריות פועלת כ־OR בתוך אותו סוג בחירה.
- מסננים מסוגים שונים מצטברים כ־AND.
- מסך הסינופסיס מוגבל בפעולת `בחר את המוצגים` לעשרים מועמדים, כדי לשמור על ביצועים וקריאות; אפשר לבחור ידנית צירוף אחר.

## עקרון ספר מול דאטהסט

בכל רשומת JSON, `passage_text` הוא קטע הספר הקבוע ו־`source_text` הוא קטע מן הדאטהסט. המערכת אוכפת את העיקרון בכל התצוגות:

- קטע הספר מוצג תמיד מימין.
- קטעי הדאטהסט מוצגים משמאל ונבחרים בידי המשתמש.
- התאמה של קטע לעצמו מוסרת בזמן בניית מודל הנתונים ואינה יכולה להופיע בקריאה, בסינופסיס, בסטטיסטיקה, בגרפים או בייצוא.

## שדרוג הסינופסיס והקריאה הרציפה

בגרסה זו נוספו שני מצבי עבודה:

1. **קטע יחיד** – קטע ספר המקור קבוע מימין, ומשמאלו מוצגים המועמדים שנבחרו מתוך הדאטהסט. אפשר לעבור לקטע הקודם או הבא, לבחור קטע ישירות מהרשימה ולשמור בחירה ידנית לכל קטע.
2. **קריאה רציפה** – רצף קטעים מספר המקור מוצג מלמעלה למטה. בכל שורה מופיע קטע המקור מול המועמדים המתאימים לו, ולכן ספרי הדאטהסט יכולים להשתנות מקטע לקטע.

### בחירה חכמה של מועמדים

- **מומלץ: חוזק וגיוון** – משלב את ציוני TEXTREUSE ומפחית כפילויות של אותו ספר או אותו דאטהסט.
- **המועמדים החזקים ביותר** – בחירה לפי הציונים בלבד.
- **מועמד מוביל מכל ספר** – מגוון את העמודות לפי ספרי הדאטהסט.
- **מועמד מוביל מכל דאטהסט** – שימושי כאשר נטענו כמה קובצי JSON.
- **יישור מלא תחילה** – נותן עדיפות למועמדים שסומנו כיישור מלא.
- **בחירה ידנית בלבד** – שומר במדויק את הבחירות שסומנו עבור כל קטע.

אפשר להפעיל בחירה אוטומטית בעת דפדוף, לקבוע כמה מועמדים יוצגו לכל קטע, לסנכרן את הגלילה בין העמודות ולייצא גם סינופסיס רציף ל־HTML.

## שכבת הידע החדשה: Passage Registry ומקורות מעורבים

ה־viewer ממשיך לקבל תוצרי TEXTREUSE בפורמט הישן, אך יכול כעת לטעון באותה בחירת מקורות גם קובצי קורפוס/metadata. הזיהוי נעשה אוטומטית:

- **TEXTREUSE JSON** — אובייקט של קטעי מקור שבכל אחד מהם `candidates`.
- **Corpus JSON** — מערך passages, wrapper נפוץ (`passages`, `items`, `segments`, `corpus`, `records`) או object-map של passages.
- **NDJSON / JSONL** — אובייקט passage אחד בכל שורה. הסיומות `.ndjson` ו־`.jsonl` נחשפות גם דרך `start_server.py`.

קובץ קורפוס אינו מחליף תוצר TEXTREUSE: הוא נבנה ל־**Passage Registry** ומעשיר את תוצאות ה־reuse לפי `location` או לפי `resource_id + passage_id`. לכן אפשר לצרף כמה תוצרי TEXTREUSE וכמה קובצי קורפוס יחד.

### שדות passage נתמכים

השכבה מנרמלת, כאשר הם קיימים, את השדות הבאים בלי למחוק את האובייקט המקורי:

- `location`, `resource_id` / `resourceId`, `passage_id` / `passageId`
- `sentence` / `analysis_text`, `orig_sentence` / `original_text`
- `segment`, `from_word`, `to_word`, `text_length`
- `title`, `he_title`, `categories`
- `versions` / `version`, `versionSource`
- `references`
- DTS אופציונלי: `dts.endpoint`, `dts.resource`, `dts.ref` או השדות המקבילים `dts_endpoint`, `dts_resource`, `dts_ref`

`location` נשמר לצורך תאימות מלאה לאחור. כאשר יש מזהים מפורשים בקורפוס, הם מקבלים קדימות בשכבת ה־Registry.

### מקורות שאינם ספריא

ספריא אינה עוד הנחת יסוד של שכבת הידע. מנגנוני ספריא, גניזה ו־VRR הקיימים נשמרו, ובנוסף קיימים:

- **Local Corpus Resolver** — מחזיר טקסט ומטא־דאטה ישירות מן ה־Passage Registry.
- **DTS Resolver** — אופציונלי, ורק כאשר passage כולל פרטי DTS.
- **Resolver Hub** — בוחר resolver לפי הנתונים. metadata מקומי נשמר גם כאשר שירות חיצוני אינו זמין.

בתוצרי TEXTREUSE חדשים אפשר לציין במפורש `source_family`, `provider`, `source_type` או `resolver`. ערכים כגון `local`, `custom`, `corpus`, `dts`, `geniza`, `vrr` אינם נכפים למסלול ספריא. ללא סימון מפורש נשמרת התנהגות התאימות הישנה.

### מה נוסף לממשק בלי לשנות את מבנה הטאבים

- מעבר בין **טקסט לניתוח** לבין **נוסח מקורי**, גם בקריאה וגם בסינופסיס.
- מטא־דאטה מקומי: Resource ID, Passage ID, segment, טווח מילים, גרסה, מקור גרסה ו־provenance.
- `References`, conflicts ו־raw passage זמינים ב־details מתקפלים כאשר הם קיימים.
- **Alignment Inspector** מציג את מקור היישור (`alignment_sequence`, matrix או HTML inferred), זוגות tokens, מזהי job/candidate ו־`synopsis_table` אם קיים.
- קטלוג הספרים מציג מקור ידע Local / DTS / Sefaria.
- אבחון הדאטה כולל כיסוי Registry, יישורים ישירים ובדיקות resolver גם למקורות שאינם ספריא.
- מפות/רשת/פיזור ממשיכים לפעול עם המזהים הישנים לצורך תאימות, אך מציגים כותרות ומזהי Resource מקומיים כאשר הם זמינים.

### עקרון תאימות

השינוי הוא additive: אין צורך להמיר datasets קיימים. שכבת ה־adapter יוצרת מודל פנימי אחיד, אך שומרת `raw`, `alignment_details`, `job_id`, `elastic_id` ו־provenance. איחוד datasets שומר גם את וריאציות רשומת המקור במקום לדרוס אותן בשקט.


## מצב קבצים גדולים וצבעי TEXTREUSE

- מעל 256MB מופעל parser זורם ב־Web Worker; מעל 1GB מופעלת גם בקשת persistent storage כאשר הדפדפן תומך בכך. הקבצים הבינוניים נשארים במסלול JSON.parse המהיר יותר.
- נתמכים NDJSON/JSONL, JSON array, object-map ישיר ו־wrappers נפוצים: `results`, `data`, `records`, `passages`, `textreuse`, `text_reuse`.
- ה־raw נכתב ל־IndexedDB בתור אסינכרוני שאינו עוצר כל batch; backpressure מופעל רק כאשר תור הכתיבה נהיה גדול. המודל הפעיל מחזיק preview קומפקטי, והטקסט/HTML המלא של הקשר הפעיל נטען לפי דרישה.
- אם IndexedDB אינו זמין או שהמכסה נגמרת, הטעינה ממשיכה במצב preview במקום להפיל את היישום; ה־raw המלא פשוט לא יהיה זמין ל־rehydration.
- רשימת מועמדים ארוכה מרונדרת במנות של 300 כדי למנוע יצירת עשרות אלפי רכיבי DOM בבת אחת.
- תרשים הפיזור משתמש ב־reservoir sampling כאשר מספר הנקודות עולה על מגבלת התצוגה, בלי לבנות קודם מערך של כל הנקודות.
- במתג `צבעי TEXTREUSE` עמוד הקריאה מציג את ה־HTML הצבעוני המקורי לאחר sanitization בטוח, ללא remapping של הצבעים בין token indices. כך הצבע נשאר על המילה המקורית. ברירת המחדל נשארת `צבעי המערכת`.
